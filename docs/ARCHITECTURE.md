# Architecture and research

## Popup and session lifetime

The Chrome action uses `popup.html` by default. **Expand** opens or focuses `index.html`; both views attach to the same session. A singleton offscreen document owns the recognizer, microphone, live buffers and transcript. The service worker creates that document and handles window/toolbar actions; it owns no model or transcript. Closing a view disconnects its channel without terminating the session.

This follows Chrome's [offscreen API](https://developer.chrome.com/docs/extensions/reference/api/offscreen), using `USER_MEDIA`, `WORKERS` and `BLOBS`. Chrome documents popup-lifetime constraints and offscreen capture in its [capture guidance](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture). `runtime.getContexts()` and a shared creation promise prevent duplicate hosts. A readiness handshake avoids sending commands before the host is listening.

Views exchange structured-clone messages over an extension-origin BroadcastChannel, so a File is transferred without Chrome runtime messaging's JSON serialization. Commands have unique IDs and acknowledgements; snapshots carry a host instance ID and increasing version. Reopened views attach to the current source, status and text. Capture state changes update the toolbar tooltip without badges. A visible permission page handles authorization when getUserMedia in the hidden host cannot prompt. **Allow and record** keeps its permission-acquiring stream alive while offscreen capture starts and throughout recording. This follows Chrome’s [one-time permission lifetime](https://developer.chrome.com/blog/one-time-permissions): the last top-level page closing can expire the grant. A direct runtime Port binds the permission window to its own recording; disconnect finishes only that recording. The stream is released on completion, failure or window closure.

## Live transcription

The published [Pianissimo model](https://huggingface.co/KlangAI/pianissimo-sv) is a noncausal FastConformer/TDT model, not a cache-aware streaming encoder. NeMo distinguishes [buffered inference for offline models from cache-aware streaming](https://docs.nvidia.com/nemo/speech/nightly/asr/inference.html). The latter needs a compatible trained encoder; adding a KV cache to this exported graph would not make it causal.

Capture runs in an [AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet), independently of model inference. It emits 100 ms blocks of 16 kHz mono PCM, including a final partial block on Stop. A flush acknowledgement is required; a suspended/interrupted audio context or missing acknowledgement is surfaced while the already received audio is still finalized. No silence gate discards quiet speech.

There is one inference in flight. Live previews use the most recent captured endpoint and begin after 1.2 seconds. Each 12-second owned interval has up to two seconds of left/right context. Words are assigned by their absolute start time. Once sufficient right context exists, that interval is committed; words in right context remain visible as provisional text. Stop processes every remaining sample, padding only sub-100 ms inputs while preserving original duration. Old audio is dropped after commitment, keeping the normal buffer small. There is no queue of obsolete preview jobs.

[Whisper-Streaming](https://github.com/ufal/whisper_streaming) and [SimulStreaming](https://github.com/ufal/SimulStreaming) are useful references for adaptive partial output and streaming attention. They are not drop-in implementations for this TDT graph. This implementation uses timestamp ownership, not LocalAgreement or AlignAtt. It reruns the buffered window; therefore provisional words can change and CPU work is higher than a model trained for native streaming. A future native-streaming Pianissimo export would be the route to lower stable-text latency.

The latest region is provisional; commitment can take roughly 14 seconds plus compute. First visible text is much earlier. Slow devices show **Catching up** after five seconds of processing lag. At a 24-second backlog, capture stops and the captured audio is finalized. The limit bounds backlog rather than silently dropping audio. Error/cancel generations prevent delayed microphone authorization or old inference from updating a newer session.

## Model and inference

`src/core/model.ts` is the model registry. The Swedish entry uses Pianissimo INT8/INT4. The multilingual entry uses the pinned istupakov ONNX export of NVIDIA Parakeet TDT v3 (INT8). Both use 16 kHz input, their own published 128-bin preprocessor, and an 80 ms TDT frame stride. The multilingual model automatically recognizes 25 European languages; it has no forced-language input or detected-language output. Selecting Multilingual does not run a language classifier or retry a failed Swedish transcription. It explicitly selects Parakeet. Future entries require compatible assets, pinned hashes, and real inference checks.

`src/core/client.ts` owns one worker and permits one public operation through its complete async lifetime, including the continuation after a worker reply. Abort/dispose terminates that worker and releases its WASM heap. Generation guards prevent cancelled operations or delayed worker events from affecting a replacement worker. A worker failure immediately releases active microphone capture and restores model-loading controls; pending file operations handle their own error recovery. Progress callbacks that throw reject their SDK operation and release its worker. `src/core/cache.ts` streams downloads into OPFS with SHA-256 verification against pinned sizes/hashes. Existing files are verified on every load. Each model has a separate revision-specific OPFS directory, preventing identical asset filenames from replacing one another. One shared Web Lock serializes cache writes/deletion across all models. Cache deletion removes both registered model directories. Language changes are rejected while work is busy; an idle change disposes the old worker and selects a supported precision before the next explicit load. No audio enters OPFS.

`src/core/engine.ts` runs the exact published ONNX log-mel preprocessor, quantized encoder and combined predictor/joiner with ONNX Runtime Web CPU/WASM SIMD. The greedy TDT loop retains predictor state for nonblank tokens, advances using duration logits, and limits zero-duration loops. Tensors and blob URLs are released explicitly.

Files use `transcribeFile()` and a pull-based `decodeAudioChunks()` iterator. Mediabunny reads explicit local container formats from a BlobSource with a 4 MiB byte cache; playlists and remote sources are excluded. A continuous WebCodecs/PCM decoder retains codec state across windows. Each 30-second owned interval has up to two seconds of context on either side. Only the overlap is retained at source rate; each native-rate mono window is converted by OfflineAudioContext to 16 kHz, then transferred to the inference worker. A dedicated window request prevents nested chunking. The audio passed to inference is at most 34 seconds (2,176,000 bytes). Native-rate PCM, resampler buffers and decoder lookahead add bounded overhead. Container indexes (notably MP3 frame tables) and transcript words still grow with duration; total process memory is not claimed to be constant. Duration discovery can scan compressed packet metadata before the first result.

There is no fixed file-size or recording-duration limit. Timestamps are relative to the primary audio track; positive container start offsets are removed. MP3 decoder priming and encoder padding can differ slightly from gapless Web Audio decoding; fixtures retain a constant roughly 25 ms initial shift without drift across windows. AbortSignal/dispose closes the input and decoder and terminates inference. Failure reasons are preserved so worker crashes cannot be mistaken for user cancellation. `decodeAudio()` remains a whole-buffer helper for small SDK inputs; the UI and `transcribeFile()` do not use it. Long and live output can differ from full-context native inference. Timestamps are model estimates; there is no diarization or translation.

## Security and verification

Manifest V3, local JS/WASM, restrictive CSP, COOP/COEP isolation, no host permissions/content scripts, and textContent rendering of transcript/file data. Permissions are `unlimitedStorage` and `offscreen`; microphone permission is requested through getUserMedia on user action. Model mirrors cannot bypass integrity verification.

Tests cover token/audio/export primitives, client cancellation, live ownership and backpressure, actual toolbar-popup closure/reattachment, offscreen capture, final flush, offline inference and comparison with native ONNX results. See [VALIDATION.md](VALIDATION.md) for evidence and test limits.
